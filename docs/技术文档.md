# 《丹阁》技术文档

> 纯前端网页游戏。零依赖、零构建，双击 `index.html` 即可运行。

---

## 一、技术栈与运行

| 项目 | 说明 |
|---|---|
| 语言 | 原生 JavaScript (ES5+ / 无模块化) |
| 渲染 | DOM 模板字符串 + Canvas 2D（秘境场景） |
| 样式 | 单文件 CSS（CSS 变量主题） |
| 构建 | **无** —— 直接打开 `index.html` |
| 依赖 | **无** |
| 存储 | `localStorage`，key = `dange_save_v1` |

**为什么不用 ES Module**：`file://` 协议下 ES Module 会触发 CORS 报错，玩家双击打不开。
因此所有脚本按顺序 `<script>` 加载，挂载到全局命名空间 `window.G`。

```html
<script src="js/data.js"></script>    <!-- 静态数据表 -->
<script src="js/core.js"></script>    <!-- 状态 / 存档 / 工具 -->
<script src="js/systems.js"></script> <!-- 业务系统 -->
<script src="js/scene.js"></script>   <!-- Canvas 秘境 -->
<script src="js/ui.js"></script>      <!-- 渲染层 -->
<script src="js/main.js"></script>    <!-- 入口 -->
```

## 三、模块职责与依赖

```
data.js  ← 纯数据，不依赖任何模块
   ↑
core.js  ← 依赖 DATA（状态、存档、派生属性）
   ↑
systems.js ← 依赖 DATA / core（业务规则）
scene.js   ← 依赖 DATA / core / UI（场景与战斗）
   ↑
ui.js    ← 依赖全部（渲染 + 事件）
   ↑
main.js  ← 启动
```

**单向依赖**：下层不知道上层的存在，跨层调用统一走 `G.UI.xxx()`（存在性检查后调用），
因此四个测试脚本可以在**无 DOM 环境**下加载 `data/core/systems/scene` 并跑通逻辑。

### 各模块关键接口

**`G.DATA`** —— 纯数据 + 少量纯函数
- `REALMS` / `STATS`：境界名与属性表（一一对应）
- `expNeed(lv)` / `cultGain(lv)`：修为曲线
- `ENEMIES[id]`：妖兽属性（`hp/atk/def/gold/loot/shape`，**没有 `exp`**，见 4.1b）
- `cultCost(lv, days)` / `meditateCost(lv)` / `talentMoneyCost(lv, cur)`：灵石开销
- `MATERIALS` / `PILLS` / `RECIPES` / `ENEMIES` / `DUNGEONS` / `CUSTOMERS` / `TALENTS` / `FURNACES` / `FIRES` / `QUALITY`

**`G.S`** —— 唯一的可变状态树（即存档）
```js
{ v, day, money, rep, insight, insightAll, talents,
  player: { level, exp, maxHp, hp, maxMp, mp, atk, def, furnace },
  bag, pills, shelf, orders, orderSeq, recipes, dungeons, buffs,
  stats, news, flags, explore }
```

**`G.P`** —— 派生属性（由状态计算，不落盘）
`realm()` `attr()` `cultPerDay()` `breakRate()` `craftRate(r)` `craftQuality(r)` `priceMul()` `repMul()` `customersPerDay()`

**`G.Sys`** —— 业务系统
`cultivate` `breakthrough` `craft` `qualityOdds` `upgradeTalent` `talentCost` `talentMoneyCost`
`shopTick` `shelfAdd` `orderTick` `orderGenerate` `orderAccept` `orderDeliver` `orderRemove`
`enterDungeon` `finishDungeon` `meditate` `marketBuy` `marketSell` `upgradeFurnace` `upgradeShelf`

**`G.Scene`** —— 秘境
`startDungeon(d)` `leave()` `getState()` `playerAttack()` `useItemInBattle()` `flee()`

**`G.UI`** —— 渲染
`init` `render` `afterAction` `toast` `confirm` `choice` `showResult` `pushLog` `gotoGuide`
`showExplore` `syncExplore` `closeExplore` `showBattle` `updateBattle` `hideBattle`

## 四、关键实现

### 4.1 时间推进（唯一入口）

```js
G.advanceDays(n, note)   // core.js
  └─ 循环 n 次：day++ → Sys.dailyTick()
       ├─ 回血回蓝、buff 倒计时
       ├─ Sys.shopTick()      零售结算
       ├─ Sys.orderTick()     订单过期/撤贴/新增
       └─ 7% 概率触发随机事件
```

**所有耗时行为都必须走 `advanceDays`**（打坐、炼丹、探险、悟道），
这样"每日结算"只需维护一个入口，不会漏算。

### 4.1b 修为只来自打坐与丹药

**妖兽不给修为**（`ENEMIES` 里根本没有 `exp` 字段，`Sys.winBattle` 只结灵石）：

```js
Sys.winBattle = function (enemy) {
  s.stats.kills++;
  const gold = U.rnd(enemy.gold[0], enemy.gold[1]);
  s.money += gold;
  ...
  return { gold };          // 没有 exp
};
```

- 修为的合法来源只剩：`Sys.cultivate`（打坐）、`Sys.takePill`（服丹，`pill.effect.exp`）
- `st.lootExp` / 重置时的修为回退也随之删除（秘境记账只剩 `gain` / `lootGold` / `lootInsight` / `kills`）

初版妖兽带 `exp`（一只 ≈ 同级打坐 2~4 天），一趟秘境够突破 1.6~3.9 次；
先砍到 1/7，四~五趟仍能顶一次突破，打坐始终被架空 —— 索性取消，
让「秘境赚钱、静室修行」各归其位。

> `test_logic.js` 的「妖兽产出审计」会断言所有妖兽都没有 `exp` 字段，
> 并真的打一场，验证修为纹丝不动。

### 4.1c 打坐日耗的标尺

```js
cultPerDay: lv => Math.round(40 + lv * 8 + lv * lv * 1.5)
```

标尺是**手感**而非公式推导：**一枚上品丹的进项 ≈ 同级 2~3 天的开销**。

| 境界 | 日耗 | 突破一境总开销 | 主力丹上品价 |
|---|---|---|---|
| 炼气期 | 50 | 950 | 聚气丹 108 |
| 金丹初期 | 118 | 3,068 | 玄冰丹 999 |
| 化神中期 | 352 | 8,800 | 雷元丹 4,042 |
| 合体初期 | 610 | 14,030 | 太初丹 16,215 |

初版 `6 + lv*3`（9~69 灵石/日）是白菜价：交几张委托就能买通一整条境界线，
灵石根本没有存在感。现在涨了约 9 倍。

> **开局不再够坐完第一境**（500 灵石 ÷ 50 = 10 天，而炼气期要 19 天）。
> 这是有意的 —— 玩家必须先去秘境采药、炼丹交单，才能攒够闭关的钱。
> 秘境不花钱，所以不存在卡死。
>
> `test_logic.js` 断言两点：开局 ≥ 5 天（不至于一上手就坐不动）、
> `聚气丹上品价 / 炼气期日耗` 落在 2~3.2 天（手感标尺不漂移）。

### 4.2 状态变更 → 渲染的统一收口

```js
G.UI.afterAction()   // 存盘 + 重绘 + 保存
```
每个 `Sys.*` 操作结束时调用它。在秘境中会改为只刷新场景 HUD，避免整页重建。

### 4.3 秘境地形生成（元胞自动机 + 连通性保证）

```js
genTerrain()   元胞自动机生成洞穴地貌
   ① 随机撒点：每格 40% 概率为障碍
   ② 迭代 4 轮：邻居障碍 ≥5 则该格变障碍、≤3 则打通（越界算障碍，边缘自然收拢成山壁）
   ③ 挑几处岩体标成水域，让画面有层次
buildTerrain() 掷 60 次取连通最好的一版（可达空地 ≥150 且可达率 ≥75% 即提前结束）
    ↓          把走不到的空地一律填成障碍
genMap()       实体按象限轮转 + 间隔约束放置；出口按 BFS 步数挑选
```

**为什么从"撒斑块"换成元胞自动机**：斑块叠加法生成的路网零碎，死胡同率约 4%，
玩家常走进死路只能原路退回；元胞自动机会长出成片的洞穴与岩体，**死胡同率降到 0.2%**。

- **出口位置按 BFS 实际步数挑选**（12~20 步、偏右、带随机），保证「走得进去也回得来」；
  行动力为 `40 + 境界×4`，出口 18 步左右时仍有 25 步可探索
- **实体放置**采用「象限轮转 + 彼此间隔 1~3 格」：既不扎堆，也不会留下一大片空区
- 玩家看到的每一块空地都一定能走到，**不存在死局**

### 4.3b 重置秘境

```js
G.Scene.resetDungeon()
  ├─ 条件：非战斗中、非弹窗暂停
  ├─ 退回：本次已到手的材料/灵石/修为/击杀数（保证净零收益）
  ├─ 重掷：st = genMap(d)，玩家回出生点，行动力恢复满值
  └─ 刷新：revealAround() + syncExplore()
```

设计意图：**用法是「进去发现路不好走，就当这趟没来过」**。
因此行动力回满、收获全部退回 —— 不留任何好处，反复重掷也刷不到便宜，纯粹是给玩家一条退路。

> 注意：感悟与材料一样是**离开秘境时才结算**的，所以重置时直接丢弃新实例的记录即可，
> 不需要（也不能）从 player 上倒扣。

### 4.3c 走过的坑：`U.shuffle` 不修改原数组

```js
// ❌ 旧实现：返回副本，原数组不变
shuffle(a) { const r = a.slice(); /* ... */ return r; }
U.shuffle(freeCells);          // 返回值被丢弃 → freeCells 还是扫描顺序

// ✅ 现在：原地打乱并返回自身
shuffle(a) { /* 原地 Fisher-Yates */ return a; }
```
后果：实体按 `freeCells` 的扫描顺序（从上到下、从左到右）填充，
**全部堆在地图第一行**，玩家看到"东西全挤在一条边上、其他地方空空荡荡"。
测试里加了「实体中心 vs 空地中心偏离 < 4.5 格」的断言来防回归。

### 4.4 品质掷骰：UI 与逻辑共用一套常数

```js
// systems.js
const Q_SPAN = 1.35, Q_MID = 0.58, Q_GOOD = 1.00, Q_TOP = 1.30;
function rollQuality(bonus) { ... }

Sys.qualityOdds(bonus)  // 用同一组常数解析反推 [下品,中品,上品,极品] 概率
```
丹房界面显示的百分比就是由 `qualityOdds` 算出的**绝对概率**（先掷成败、成丹后再定品质），
改阈值只需改一处，UI 自动跟上。测试用 20 万次蒙特卡洛校验偏差 < 0.6%。

### 4.5 存档与版本迁移

```js
const SAVE_VER = 2;   // 1 = 炼气分九层的旧体系，2 = 炼气期单层
G.load()
  ├─ data.v === 1  → migrateV1(data)   旧档迁移
  ├─ data.v !== 2  → 放弃（当作新档）
  └─ 合并默认值 → 兜底数组结构 → 按境界补齐丹方/秘境 → G.S = s
```
- **合并顺序有坑**：必须先留好默认值引用再 `Object.assign`（详见 6.1）
- 迁移会保留丹药带来的永久加成、日期、灵石、声望、天赋、货架、丹炉
- 迁移后立即回存，避免每次启动重复迁移

### 4.6 渲染层

- **模板字符串 + `innerHTML`**：整块重绘，简单直接
- **日志走增量**：`UI.pushLog()` 只追加一行，不重建整个列表
- **事件委托**：所有交互统一用 `data-act` 属性 + 顶层委托，避免重复绑定
  ```html
  <button data-act="craft">开炉炼丹</button>
  ```
- **Canvas 场景**：`requestAnimationFrame` 循环，绘制迷雾内可见格 + 实体 + 飘字

#### 滚动位置要自己记

整块 `innerHTML` 重建会把滚动位置清零 —— 在丹房点一张丹方，列表就跳回开头。
`render()` 因此会在重绘前后搬运一次滚动位置：

```js
function render() {
  const stay = lastTab === tab;              // 同一标签内重绘才保留，切标签该回顶部
  const keep = stay ? scrollKeep() : null;   // #view 与 .recipe-list 两处都记
  lastTab = tab;
  ...
  if (keep) scrollRestore(keep);
  else el.view.scrollTop = 0;
}
```

要记**两个**滚动容器：宽屏时丹方列表自己滚（`.recipe-list { max-height: 560px }`），
窄屏（<940px）单列布局时整页 `#view` 滚 —— 少了哪一个都会跳。

### 4.7 战斗层挂在 body 级

战斗面板原先是 `.canvas-box` 里的 `position: absolute; inset: 0` 层。窄窗口下 canvas 只有两百来像素高，
392px 高的面板被 `.canvas-box { overflow: hidden }` 上下裁掉 —— **"出击"按钮整个落在裁剪区之外，点击命中的是下面的提示文字**
（实测 `elementFromPoint` 返回 `.explore-hint`，"进秘境点不到攻击"就是这么来的）。

现在 `#battle-layer` 放在 `index.html` 的 body 末尾，与 canvas 解耦：

```css
#battle-layer { position: fixed; inset: 0; z-index: 55; display: flex; align-items: flex-start; overflow-y: auto; }
.bt-panel { margin: auto; }   /* 富余时居中；面板高于视口时从顶部起可滚 */
```

- 面板永远相对**视口**居中，与 canvas 尺寸、`#view` 滚动位置都无关
- `margin: auto` + 整层 `overflow-y: auto`：再矮的窗口也能滚到按钮
- 层级：`#battle-layer`(55) < `#modal-layer`(60) < `#toasts`(80)，所以战斗里的「服丹」弹窗仍盖在面板上

## 五、测试体系

测试脚本在 `z-TempForAI/`，全部基于 Node + `vm.runInThisContext` 做实现在无 DOM 环境下的逻辑校验。

| 脚本 | 覆盖范围 | 何时必须跑 |
|---|---|---|
| `test_logic.js` | 修炼/突破/炼丹/品质概率/商店/订单/战斗/妖兽产出审计/经济审计/长线模拟 | 改任何业务逻辑 |
| `test_realm.js` | 属性单调性、解锁空窗、战斗强度对齐、旧档迁移（9 组用例） | 改境界/属性/解锁 |
| `test_mats.js` | 29 味药的采集地/宝箱/掉落/市集四类来源审计 | 改材料/配方/秘境 |
| `test_map.js` | 6 秘境 × 400 局地形连通性 + **出口步数(4~26)** + 1200 局随机游走 | 改地图生成 |
| `debug_maze.js` | 诊断用：死胡同率、视野内可用格、出口步数分布 | 调地形参数时参考 |

**测试环境的三条注意事项**（血泪教训）：
1. 必须屏蔽随机事件：`G.Sys.randomEvent = () => {}`（劫修/行商会增减灵石，干扰断言）
2. 突破有失败概率：断言属性前要循环重试到升级成功
3. 长线模拟的随机性很大，**不要用它做严格断言** —— 改为宽松健全性检查 + 确定性审计

## 六、踩过的坑

### 6.1 存档合并把自己赋给自己
```js
// ❌ 错误：Object.assign(base, data) 之后 base.stats 已指向存档里的旧对象
const base = newGame();
G.S = Object.assign(base, data);
G.S.stats = Object.assign(base.stats, data.stats);   // 自己赋自己，新字段全丢

// ✅ 正确：先留默认值引用
const baseStats = base.stats;
const s = Object.assign(base, data);
s.stats = Object.assign({}, baseStats, data.stats || {});
```
症状：旧存档加载后新增字段为 `undefined`，界面显示 `NaN`。

### 6.2 Web Crypto 与 file:// 
不使用 `crypto.randomUUID()` 等需要安全上下文的 API（`file://` 下不可用），
ID 统一用自增序号：`'ord' + (++s.orderSeq)`。

### 6.3 Canvas 浅色主题的可见性
浅底上不能用深色描边画文字，改为**深色字 + 白色描边**：
```js
ctx.lineWidth = 3.5; ctx.strokeStyle = 'rgba(255,255,255,.92)';
ctx.strokeText(text, x, y); ctx.fillStyle = color; ctx.fillText(text, x, y);
```

### 6.4 变量名冲突
长线测试脚本里模拟秘境探索的函数内使用了 `U.rnd`，但 `const U = G.U` 声明在下方，
导致 `ReferenceError: Cannot access 'U' before initialization`（TDZ）。
**教训**：把共享常量声明在脚本顶部。

### 6.5 事件监听的重复绑定
秘境场景的 `keydown` 监听用 `bound` 标志位防重，退出时必须 `removeEventListener`，
否则会跨场景累积。

## 七、扩展指南

### 加一味新药材
1. `data.js` → `addMat(id, name, tier, price, desc)`
2. 加进某个秘境的 `gathers` / `chests`，或某只妖兽的 `loot`（数组里重复出现可以调权重）
3. 若要上架市集，加进 `MARKET` 数组
4. 跑 `node z-TempForAI/test_mats.js` 验证来源审计

### 加一张新丹方
1. `data.js` → `addPill(...)` 定义丹药
2. `RECIPES` 加一条：`{ id, pill, qty, mats, req, days }`
3. `req` 建议落在**当前有空窗的境界**上（跑 `test_realm.js` 查看）
4. 跑 `test_mats.js`（材料来源）+ `test_realm.js`（解锁节奏）

### 加一处新秘境
1. `data.js` → `DUNGEONS` 加一条，指定 `req` / `days` / `vision` / `enemies` / `gathers` / `chests`
2. `scene.js` → 在 `THEME` 里加一套浅色配色
3. 跑 `test_map.js`（连通性）+ `test_logic.js`（战斗强度会按新 `req` 重算）

### 调整经济数值
改 `data.js` 的 `COST` / `MARKET_BUY` / `MARKET_SELL` / 各 `PILLS.price` 后，跑 `test_logic.js`：
- 「经济审计」会检查"买料零售是否普遍亏本"
- 「经济健康度」会检查"秘境赚钱效率 ≥ 打坐开销 × 3"
- 「修行开销」会检查"一枚上品丹 ≈ 2~3 天打坐"的手感标尺

### 调打坐开销 / 修为产出
- 改 `COST.cultPerDay` 后跑 `test_logic.js`，看「修行开销」的日耗对照表与锚点断言
- **妖兽不给修为是刻意的**：想让秘境更肥，就调 `enemyCount` / `enemies` 池权重 / `gold`，别加 `exp`

### 调平衡前的四条自检
1. 开局 500 灵石够不够坐上几天？（现 10 天，够撑到第一趟秘境回来）
2. "买料 → 炼丹 → 零售"会不会变成正收益？（不能，会架空秘境探索）

### 移动端适配

游戏以桌面 web 为主，手机只保证「能用、不乱、点得到」，**桌面端样式一行不改**。断点全在 `style.css` 末尾：

| 断点 | 调整 |
|---|---|
| ≤ 940px（原有） | 右栏收窄到 220px、网格改单列 |
| ≤ 720px | HUD 折两行、主体单列（见闻压成底部 92px 一条）、标签页收窄、长列表改为随整页滚、战斗面板 2×2 大按钮、弹窗铺满 |
| ≤ 420px | 品牌字 / 标签 / 数值再缩一档 |

窄屏的三条硬规则（都是实测踩出来的）：

1. **grid 子项补 `min-width: 0`**（`#stage`）：否则被列表内容的 min-content 顶宽，整页出现横向滚动条
2. **grid 列表写成 `minmax(min(310px, 100%), 1fr)`**：容器比列宽还窄时自动收成一列，而不是撑破父级
3. **`.hud-stats` 必须 `flex-wrap: wrap`**：四个数值不换行，HUD 会把整个 `#app` 撑到视口之外

验证方式：VS Code 集成浏览器可压到 **312×608**（比 iPhone SE 还窄），逐个标签页断言
`document.documentElement.scrollWidth === innerWidth`，再实测「进秘境 → 撞妖兽 → 点出击」全流程与按钮命中（`elementFromPoint`）。
